# FDE 岗位雷达：2026 年 8 月快照

核验日期：2026-08-21

> 这是一份基于有限官方样本的能力雷达，不是全球招聘数量统计，也不是任何公司的内部面试说明。

## 1. 结论先行

2026 年的 FDE 已经不是单一岗位，而是一个围绕“现场交付与产品学习”形成的岗位家族。共同内核没有变：深入客户环境、亲手解决问题、让方案进入生产、把反馈带回产品。变化发生在工程对象上：过去常见的是数据集成、定制应用和云迁移；现在越来越多岗位直接要求生产 Agent、MCP、skills、评测基础设施、上下文控制和安全治理。

对候选人最重要的反常识判断是：**模型知识的边际价值在下降，部署判断的边际价值在上升。** 会调用更强模型的人越来越多；能判断该不该用 Agent、如何限制权限、怎样构造黄金集、故障后如何恢复、如何让业务团队真正采用的人仍然稀缺。

## 3. 五类常见 FDE

### 3.1 核心平台型

代表任务：把通用平台部署进复杂客户环境，同时把共性需求带回核心产品。

面试重点通常是系统设计、代码、数据集成、权限、部署和产品化反馈。候选人如果只会定制，不会识别共性，就容易被判断为“优秀项目工程师，但平台杠杆不足”。

### 3.2 AI 实验室型

代表任务：把前沿模型变成稳定工作流，用评测和现场反馈影响模型与产品路线。

这里最容易误判。岗位并不是要求候选人背更多模型参数，而是要求理解模型的非确定性怎样改变产品设计：需要黄金集、trace、回归门禁、权限、人工审批、回退和成本路由。MCP、sub-agent、skills 只是新的交付载体，可靠性责任并没有消失。

### 3.3 数据与模型供应链型

代表任务：为训练、评测或企业应用构建高质量数据流和运营系统。

这类岗位会放大 SQL、Python、分布式处理、schema、数据质量、幂等、回放和运营工具能力。只准备 RAG 对话系统会漏掉真正的主战场。

### 3.4 垂直行业型

代表任务：进入医疗、金融、政府、风控、审计等专业工作流，把行业约束变成系统行为。

面试官不一定要求候选人一开始就是行业专家，但会观察学习速度、风险敏感度和能否获得专业用户信任。强候选人会主动区分“模型建议”“业务决策”和“受监管动作”，并设计证据链和升级机制。

### 3.5 迁移与现代化型

代表任务：平台迁移、前端现代化、性能优化和 AI 采用并行推进。

这提醒候选人：FDE 并不等于 AI FDE。经典软件工程、代码审计、性能、CI/CD、可维护性和客户赋能仍然是许多岗位的核心。

## 4. 2026 能力重心的六个变化

### 变化一：从“会做 demo”转向“能证明采用”

交付成功不再等于接口返回 200，也不等于离线准确率达到某个数。更完整的证据链是：目标用户真的使用，关键步骤时间下降，错误或风险受控，业务指标有改善，客户团队能继续维护。面试时应主动把模型指标、系统指标和业务指标分层。

### 变化二：从 prompt engineering 转向 context engineering

Agent 的表现不只由系统提示决定，还取决于工具定义、可访问数据、消息历史、示例、检索策略和运行时状态。上下文越来越像一个有预算、有权限、有生命周期的数据平面。候选人要能解释怎样减少工具重叠、按需加载、压缩历史、防止污染和保护敏感内容。

### 变化三：从工具调用转向受治理的行动

一旦 Agent 能写数据库、发邮件、创建工单或调用生产系统，问题就不再是“function call 能不能成功”，而是身份、最小权限、幂等、审批、补偿、审计和撤销。MCP 让工具更易接入，同时扩大了授权与供应链边界。

### 变化四：从单次响应转向长任务生命周期

长任务会经历断线、限流、进程重启、人工等待和工具重试。A2A 的任务、订阅和推送通知，MCP 的 Tasks 扩展，以及 durable execution 的兴起，都说明生产系统必须把执行状态与浏览器连接、单个 Pod 和单次模型调用解耦。

### 变化五：从“上线后观察”转向持续评测

模型、提示、知识库、工具和业务流程都会变化。黄金集不是一次验收文件，而是回归控制面。强答案会说明数据如何从真实失败中进入评测集、如何分层诊断检索与生成、怎样处理 judge 漂移，以及上线门禁与线上反馈如何连接。

### 变化六：从定制项目转向可复用现场产品

FDE 的长期价值来自缩短下一次交付。每次项目都要回答：哪些是客户特有，哪些应该成为平台能力，哪些应该沉淀成模板、skill、connector、eval 或 runbook。如果所有知识都留在个人脑中，团队无法形成复利。

## 5. 面试准备的实际调整

### 对软件工程师

不要只补 AI 名词。重点练习客户发现、业务指标、采用、权限和风险沟通；把一个真实项目重写成“从模糊需求到生产影响”的故事。

### 对数据工程师

你的优势是现实数据和可靠管道。需要补的是面向用户的产品闭环、模型非确定性、评测和快速原型表达。不要低估数据同步、血缘和回放在 AI FDE 中的价值。

### 对解决方案架构师或售前

你的优势是发现和沟通。风险是停留在白板。准备一个能证明你亲手写代码、测试、调试和承担上线结果的案例；清楚说明个人贡献。

### 对 AI 应用工程师

不要把所有问题都 Agent 化。面试中主动提出确定性工作流、规则或普通按钮可能更合适，往往比盲目增加自治更能显示判断力。

## 6. 未来三年的判断与边界

以下是基于当前岗位和标准演进做出的推断，不是已发生事实。

1. **FDE 会进一步分层。** 通用“既懂一切又负责一切”的岗位会减少，AI builder、数据基础设施、行业工作流、迁移和部署领导等子类型会更清晰。前提是企业 AI 采购继续从试验转向规模部署。
2. **可复用交付资产会成为核心产出。** connector、MCP server、skill、eval suite、policy 和 rollout template 会像过去的 SDK 与 reference architecture 一样重要。失效边界是协议生态碎片化或企业安全策略拒绝动态工具接入。
3. **Agent 可靠性会吞并一部分传统 MLOps 与工作流工程。** 状态、重试、审批、回放和审计将进入统一交付栈。若模型自治的经济价值低于确定性自动化，这一趋势会在高风险行业放缓。
4. **面试会更重视现场证据。** 可运行的 demo 仍重要，但“如何发现、如何评测、如何灰度、如何恢复、如何交接”会占更大比重。只靠刷题难以覆盖。
5. **最强 FDE 不会被 Agent 简单替代。** AI 可以加速代码、排查和平台操作，甚至出现 AI FDE 产品；但决定做什么、赢得信任、处理组织冲突、承担结果并把局部经验抽象成产品，仍需要高质量的人类判断。这个结论成立的边界是工作流高度标准化、风险低且客户差异足够小。
