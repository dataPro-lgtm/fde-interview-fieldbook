# 项目更新手册

## 月度来源巡检

GitHub Actions 每月检查 `data/sources.json` 的 `last_checked`。每个来源按自己的 `refresh_days` 执行：岗位通常 30 天、活跃协议 45 天、标准和稳定方法通常 90 天。超期后会生成或更新 `Source refresh required` Issue。

维护者按以下顺序处理：

1. 打开原始链接，确认页面是否仍在、内容是否改变；
2. 若职位下线，保留历史快照语境，不推断岗位永久取消；
3. 若职责改变，更新岗位雷达和相关章节；
4. 若协议有新版本，检查新增、弃用和迁移影响；
5. 更新 `last_checked` 和 `CHANGELOG.md`；
6. 运行 `python3 scripts/validate_repo.py`。

## 季度岗位雷达

每季度新增一个快照文件，不覆盖旧文件。快照至少包含：

- 官方样本与核验日期；
- 新出现或明显增强的能力要求；
- 减弱或消失的信号；
- 对面试准备的调整；
- 推断、成立条件和失效边界。

## 问题与案例更新

新增内容必须映射到总评分表维度。优先补“现有内容无法训练的能力”，而不是扩充同义题。

一个新案例至少包含：当前工作流、利益相关者冲突、数据/系统约束、thin slice、关键设计、评测、发布、失败注入和产品化。不得使用可识别的真实客户细节。

## 年度发布

年度版本应：

- 复核全部官方来源；
- 归档当年岗位雷达；
- 校准评分表行为锚点；
- 删除已弃用且无历史价值的技术建议；
- 发布 release notes，说明候选人应调整什么；
- 明确仍未解决的争议，而不是强行给出统一答案。
