# FDE 岗位雷达档案

岗位雷达不是招聘数量榜，也不是面经汇总。它按季度保存公开的一手岗位证据，回答三个更稳的问题：FDE 正在分化成哪些工作类型，哪些生产责任开始变成显性要求，候选人的准备重点应如何调整。

后续季度只新增文件，不覆盖旧文件。这样才能区分“市场真的出现了新信号”和“我们只是改写了上一版措辞”。

## 怎样读地域信息

地域视图使用三层口径，不能混在一起：

1. **岗位所在地**：招聘页面明确写出的办公或工作地点；
2. **客户覆盖范围**：页面明确写出的客户出差或服务范围；
3. **候选人要求**：页面明确写出的语言、出差、工作方式或行业经验。

东京岗位要求日英双语，并不等于所有日本 FDE 都采用相同要求；伦敦岗位服务欧美客户，也不等于欧美岗位数量增加。一个地区只有单一官方样本时，快照只能写成案例，不能升级为区域规律。

## 不使用什么数据

- 不抓取私人招聘系统或推断未公开 headcount；
- 不把搜索页当日结果数当成市场规模；
- 不用薪资聚合站推断岗位级别；
- 不把一位候选人的面试流程写成地区惯例；
- 不因职位页面下线就判断岗位或团队已经取消。
