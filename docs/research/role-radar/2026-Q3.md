# FDE 岗位雷达：2026 Q3

核验日期：2026-08-21

> 这是一份基于有限官方样本的能力快照，不是全球招聘数量统计，也不是任何公司的内部面试说明。结构化证据见 [`data/role-radar/2026-Q3.json`](../../../data/role-radar/2026-Q3.json)。

## 1. 本季度真正值得记住的变化

FDE 正从一个宽泛标题，变成一组共享同一工作方式、但工程主轴不同的岗位家族。公开样本里已经能同时看到核心平台 FDE、AI builder、forward-deployed software engineer、数据基础设施 FDE、受监管行业 FDE 和 technical deployment lead。

这不是简单的“岗位变多”。更重要的变化是，企业开始把过去依赖个人经验的现场交付拆成可识别的专业能力：发现工作流、亲手构建、生产发布、采用、评测、可靠性、知识转移和产品反馈。候选人如果仍把自己描述成“什么都懂一点的 AI 通才”，会越来越难解释自己究竟能在哪个交付断点上承担责任。

本季度的第二个变化，是协议和 Agent 名词已经进入岗位要求，但真正稀缺的仍不是名词。Anthropic 的岗位把 MCP server、sub-agent 和 agent skill 写成生产交付物；Diligent 要求黄金集、回归、trace 和完整 Agent 生命周期；Vercel 同时寻找迁移专家和 AI builder。它们共同指向同一件事：**企业买的不是一个会调用工具的 Agent，而是一条能被信任、恢复、审计和交接的工作流。**

## 2. 样本怎样选，为什么不统计岗位总数

本快照只使用雇主岗位页、官方岗位索引和官方产品/规范资料。岗位搜索页会持续变化，同一天也可能因为新职位、下线职位、筛选状态或页面展示问题产生不同结果。因此，本项目记录可复核的角色类型、地点和要求，不把搜索页上方的总数保存为增长指标。

这个限制很重要。公开职位数受到招聘节奏、页面更新和组织命名影响，它不是市场需求、团队人数，更不是未来录用数量。我们宁可少给一个漂亮数字，也不把不稳定数据包装成趋势。

## 4. 六类岗位画像

### 4.1 核心平台型

把通用平台部署进复杂客户环境，并把重复需求带回产品。面试要证明集成、权限、上线和抽象能力。只会写客户特例，不能识别平台共性，长期会把团队拖进无限定制。

### 4.2 AI 实验室型

把前沿模型能力变成稳定工作流。重点不是背模型参数，而是处理非确定性：上下文、工具、评测、权限、灰度、回退和采用。MCP、skills 与 sub-agent 是交付载体，不是可靠性本身。

### 4.3 数据与模型供应链型

为数据生成、处理、训练或评测建立客户和运营系统。SQL、Python、分布式处理、schema、幂等、回放、质量和运营工具会比聊天界面更重要。

### 4.4 垂直行业型

进入医疗、金融、政府、审计、风控或其他高语境流程，把专业责任和法规要求变成系统行为。强候选人会区分模型建议、业务决定和受监管动作，并为每层设计证据与升级路径。

### 4.5 迁移与现代化型

负责代码审计、平台迁移、性能和企业 AI 采用。它提醒候选人，FDE 并不天然等于 AI FDE；经典工程深度、增量迁移和客户赋能依然能构成完整主轴。

### 4.6 部署领导型

当部署规模扩大后，会出现同时管理项目组合、客户关系、交付节奏和复用机制的负责人。这个方向不是“不再写代码”，而是决定在哪些关键点亲自下场、怎样让多个交付不依赖英雄式救火。

## 5. 地域视图：能说什么，不能说什么

### 北美样本：角色分工更细，但不是统一模板

北美样本里同时出现核心平台、数据基础设施、迁移、AI builder、行业型和部署领导岗位。候选人最现实的准备方式，不是把能力清单越写越长，而是先选择自己的工程主轴，再证明自己可以从这个主轴走到客户采用和产品反馈。

边界是：样本集中在美国科技公司和少数城市，不能代表北美全部行业，更不能说明每家公司都采用同样分工。

### 欧洲样本：监管工作流是清晰案例，不是区域定论

伦敦样本把 Agent 可靠性放进审计、风险和合规工作流，强调黄金集、回归、trace 与专业用户信任。它适合提醒候选人：在高风险流程里，“为什么不自动化”与“怎样证明可追责”跟模型能力同样重要。

边界是：本季度结构化数据只有一个欧洲落地样本，只能说明一种明确存在的岗位形态，不能写成“欧洲 FDE 普遍更重合规”。

### 东亚样本：本地语言是交付接口，工程责任没有降低

东京岗位明确要求日英双语，并把出差范围主要放在日本；与此同时，它对发现、系统设计、构建、生产发布、采用和产品反馈的要求与全球 FDE 主线一致。

对候选人而言，本地语言不是简历上的附加标签，而是发现隐性流程、处理跨团队误解、写清验收和推动采用的交付接口。但语言能力也不能替代代码与生产证据。边界是：详细要求来自单一东京岗位，不外推到整个东亚。

### 其他已观察地区：只记录存在，不制造画像

官方索引还出现新加坡、悉尼和阿布扎比岗位。当前证据只足以说明这些地点存在公开岗位，尚不足以比较当地能力权重。候选人应回到实时岗位页核对语言、出差、工作许可、客户覆盖和技术主轴。

## 6. 对面试准备的实际调整

### 先确定主轴，再补齐 FDE 闭环

把自己放进下面一个主轴：平台/全栈、数据基础设施、AI 工作流、垂直行业、迁移现代化或部署领导。然后检查你是否能从该主轴讲到发现、上线、采用、事故、交接和复用。主轴让你可信，闭环让你像 FDE。

### 把“会 Agent”改写成生产证据

不要只写使用了哪些框架。准备说明：为什么需要自治、工具权限如何绑定、状态存在哪里、重复动作如何防止、谁批准高风险步骤、怎样回放失败、黄金集如何增长、什么指标会触发回滚。

### 地域准备必须回到当前岗位文本

语言、出差、办公方式和行业要求变化快。面试前重新打开岗位页，把每一项要求映射到自己的证据；没有证据的地方写成待验证和补强计划，不要用对某个国家的泛泛印象代替岗位分析。

### 作品集要暴露边界

一个可信作品集会写清真实用户还是模拟练习、哪些指标实际测过、哪些安全控制只是设计、哪些外部系统没有接入。FDE 面试越来越看重判断的可校验性，夸大规模会直接破坏信任。

## 7. 未来 12—24 个月的判断

以下是基于本季度样本的推断，不是已经发生的事实。

1. **岗位标题会继续分层。** 当企业部署从少数试点进入项目组合，工程主轴和领导责任会更清晰。失效边界是 AI 部署投资收缩，或者企业重新把现场工作并回传统专业服务。
2. **可复用交付资产会成为评价对象。** connector、MCP server、skill、eval suite、policy 和 rollout template 会越来越像过去的 SDK 与 reference architecture。失效边界是协议生态碎片化，或安全政策拒绝动态工具接入。
3. **Agent 可靠性会与工作流工程合流。** 状态、重试、审批、回放、审计和恢复会进入同一交付栈。若自治的经济价值长期低于确定性自动化，高风险行业会更偏向固定编排。
4. **地域差异首先体现在交付接口，而不一定体现在核心工程。** 语言、出差、采购、合规和本地伙伴会改变发现与上线方式，但数据、权限、可靠性和采用责任仍有共同底座。这个判断需要更多跨公司地区样本才能加强。

## 8. 下一季度怎样更新

下一份快照将新增文件，不修改本季度事实记录。更新时优先寻找：

- 同一岗位家族跨季度是否持续存在；
- 是否出现新的地区或行业样本；
- 能力要求是新增、增强，还是只是措辞变化；
- 下线页面是否有替代岗位或产品化信号；
- 哪些推断获得第二个独立官方来源，哪些仍应保持单例边界。
