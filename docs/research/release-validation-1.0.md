# v1.0.0-rc.1 发布候选验收与完成审计

> **状态：** A1 内容、练习、数据契约、自动化与可重现发布清单通过；四项外部门禁均为 `not-run`<br>
> **核验日期：** 2026-08-22<br>
> **版本：** `1.0.0-rc.1`，release candidate，不是 stable<br>

## 1. 本次审计依据什么判断完成

v1.0 的目标不是把版本号从 0.9 改成 1.0，而是证明读者入口、训练资产、案例、评分、双语路径、来源维护和发布验证形成一个可重现系统。审计逐项对应 `docs/research/version-plan-0.6-to-1.0.md`、`ROADMAP.md` 和各版本验收记录；没有用“文件很多”或“测试是绿的”代替真实外部效果。

## 3. 可独立使用的主线

读者可以从中文或英文学习地图选择目标岗位和时间，再通过 7、14 或 30 天路径产生可检查产物。主线不是通读：

```text
目标岗位与基线
-> 当前工作流与 mission
-> 编码 / 数据 / 系统设计证据
-> 生产 AI、风险与恢复
-> 盲练案例与分轮决策
-> 原话评分、修复、复评
-> JD 定向、作品集与现场交付
```

案例主持人有候选人/主持人材料隔离、证据释放、专项评分和复盘契约。评审者有 `N/O`、信心、分歧分类和裁决协议。维护者有来源、双语、学习路径、案例和发布数据清单。

## 4. 发布清单怎样工作

`data/release-manifest.json` 不逐项手写 200 多个摘要。`scripts/validate_release_manifest.py` 读取 Git index 中除清单自身外的每个文件，针对每个文件计算路径、字节数和 SHA-256，再按 `root`、`.github`、`data`、`docs`、`interview-kits`、`scripts`、`tests` 和 `other` 分组，最后生成唯一内容根。

这样既避免清单自引用，也能发现任意已跟踪内容漂移。清单同时登记版本、A1 证据级别、库存数量、验证命令、四项外部门禁和禁止扩大解释。新增、删除或修改已跟踪文件后，如果不刷新清单，`--check` 必须失败。

## 5. 全量回归命令

核心无网络契约：

```bash
python3 scripts/verify_release.py
```

完整内容、渲染和网络审计：

```bash
python3 scripts/verify_release.py --full --network
```

已提交候选的最终检查：

```bash
python3 scripts/verify_release.py --full --network --require-clean
```

一键入口依次运行仓库内部链接与来源、案例、研究、岗位包、学习路径、校准、双语与档案、全部单元测试、Python 编译、空白差异、两版 Markdown lint、全部 Mermaid 渲染、公开外部链接和发布清单内容根。

## 6. 自动化观察结果

本次候选的机器库存和最终摘要以 `data/release-manifest.json` 为准，避免在文档中复制易漂移的哈希。内容检查观察到：

- 10 套 Field Case Lab 与 72 个登记文件；
- 3 条学习路径与 29 个有完成证据的 session；
- 8 个校准场景与 13 个证据锚点评分；
- 16 对中英文核心学习结果；
- 17 条当前来源与 17 条年度档案元数据；
- 33 张 Mermaid 图实际渲染；
- 21 条公开外部链接无硬失败和软失败。

单元测试数量、索引文件数量、字节数和内容根由最终清单与命令输出报告，不在清单生成前写死。

## 7. 人工完成审阅

本轮人工审阅确认：

1. README 能按症状、时间和岗位路由，不要求从头通读；
2. 每个训练阶段留下另一人可检查的产物；
3. 十套案例的风险不是用不同背景复写同一道架构题；
4. 评分以原话和产物为单位，不用术语、资历或流畅度代替；
5. 中文和英文保留相同风险、owner、完成标准与未验证边界；
6. 来源档案不复制网页正文或受限材料；
7. 历史上没有证据的“已完成学员试用”已重新打开；
8. `VERSION`、CITATION、README、Roadmap、Changelog、CI 和发布清单的版本状态一致。

## 8. 四项外部门禁

以下门禁只能由真实非作者参与者产生，当前都为 `not-run`：

1. **独立训练路径：** 非作者读者完成注册路径且作者无需临场修补；
2. **独立案例主持：** 非作者主持每套准备晋级的案例并记录阻塞；
3. **独立评分校准：** 两位评审盲评、裁决分歧，并由分歧触发材料修订；
4. **双语独立使用：** 中英文读者均能找到并完成等价核心练习。

这些门禁不会被合成学员、模型扮演评审、作者自测或没有记录的口头反馈替代。真实证据进入仓库前必须删除姓名、公司、客户数据、面试题和其他可识别信息。

## 9. 发布结论

`1.0.0-rc.1` 达到可验证、可维护、具备独立使用路径的 A1 发布候选标准。仓库可以公开为 v1.0 release candidate，并邀请真实非作者按既定协议试用。由于四项外部门禁尚未满足，`promote_allowed` 必须保持 `false`，不得打 stable 标签或宣传为“已经证明有效”。

稳定版晋级条件不是再增加篇章，而是用真实运行发现哪些说明、证据释放、评分锚点或双语路径仍依赖作者，然后修订并重新生成发布清单。
