# v0.7 十套生产案例验收记录

> **状态：** A1 案例结构、风险覆盖与自动化验收通过；独立主持均未执行<br>
> **核验日期：** 2026-08-21<br>
> **适用范围：** 十套 Field Case Lab、案例清单 v2、分轮证据、专项评分、风险元数据、边界测试与导航

## 1. v0.7 为什么增加案例

前三套 Field Case Lab 已覆盖数据迁移、隔离环境和生产事故，但仍不足以检验 2026 年 FDE 常见的七类现场责任：Agent 工具副作用、知识生命周期、长任务恢复、AI 回归、跨境边界、用户采用和连接器产品化。

新增案例不是为了扩大题库，而是让同一套 FIELD 判断在不同生产风险下接受压力。十套组合同时覆盖计划型交付、事故型响应、组织采用和现场到产品的抽象。

## 2. 案例组合

| 案例 | 主要风险 | 候选人必须证明的核心判断 |
| --- | --- | --- |
| 数据平台迁移 | 迁移、生命周期、采用 | 双跑、对账、切流、回退和消费者迁移 |
| 隔离环境 AI | 安全、评测、采用 | 在供应链和运维约束下形成可复现证据 |
| 生产事故 | 事故、评测、数据 | 先保护和保存证据，再定位第一偏离层 |
| Agent 工具副作用 | 写操作、权限、事故 | 稳定业务身份、幂等、未知结果和分阶段放权 |
| 知识同步生命周期 | 删除、权限、对账 | 区分 tombstone、快照缺失、软删和撤权 |
| 长任务断点续传 | 持久执行、副作用 | 连接与任务解耦、租约 fencing、事件重放和恢复 |
| AI 评测回归 | 指标、版本、风险 | 验证测量、固定版本、单变量实验和切片恢复 |
| 跨境 AI 部署 | 区域、安全、采用 | 数据目的、正式 owner、最小共享和阶段交付 |
| 采用恢复 | 工作流、评测、产品 | 用行为和实验修复价值，不制造强制采用 |
| 连接器产品化 | 契约、迁移、复用 | 稳定核心、源适配、第二源验证和渐进迁移 |

## 3. 案例文件与数据契约

每套案例包含候选人简报、主持人简报、至少三轮证据、专项评分和参考复盘。清单 v2 进一步要求：

- `difficulty` 只能是 intermediate 或 advanced；
- `risk_domains` 至少两个、不得重复且必须来自允许集合；
- `field_skills` 至少三个不同 FIELD 阶段；
- `release_gates` 至少两条可观察门禁；
- `human_validation` 必须说明状态、独立运行次数和边界备注；
- `not-run` 必须对应零次，`independent-run` 至少一次，`multi-run` 至少三次；
- 十个指定风险域必须在案例组合中全部覆盖。

候选人材料仍不得链接主持人材料、证据目录、评分或复盘。CSV 必须为矩形，JSON 必须可解析，所有文件必须登记且留在各自案例目录。

## 5. 人工内容审阅

本轮逐套检查：

1. 候选人是否有足够背景但看不到答案；
2. 主持人能否根据有效提问释放证据，而不是猜关键词；
3. 新证据是否真的会迫使候选人更新判断；
4. 评分是否与场景风险绑定，而不是复制通用形容词；
5. 一票否决是否对应不可接受的生产行为；
6. 复盘是否讲机制、替代方案和失效边界；
7. 合成数据是否避免真实客户、身份、凭证和泄露内容。

## 6. 尚未验证的部分

所有案例的 `human_validation.status` 当前都是 `not-run`。这表示：

- 尚未由非作者主持人完整运行；
- 尚未观察证据释放是否需要作者额外解释；
- 尚未比较两位评审在专项锚点上的分歧；
- 尚未确认 60/75/90 分钟安排是否适合真实参与者；
- 不具备任何“案例经过独立评审”或“提高面试结果”的证据。

自动化不能替代这些门禁。未来每次真实运行应提交隐私安全的阻塞点、评分分歧和材料修订，不收集真实雇主题目或客户数据。
