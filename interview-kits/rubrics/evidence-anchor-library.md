# 跨角色证据锚点库

> 这不是标准答案库。它帮助评审区分危险、知道、独立交付和组织杠杆，并为分歧设计下一层追问。每个分数仍必须引用本次回答的原话或产物。

## 1. 客户发现与问题拆解

| 等级 | 可观察行为 |
| --- | --- |
| 1 | 接受表面需求，直接选择架构；无视不可逆风险或拒绝澄清 |
| 2 | 会问用户和目标，但基线、非目标、责任或验证仍依赖提示 |
| 3 | 还原角色、触发、决策、动作和失败；定义基线、thin slice、门禁和反证 |
| 4 | 发现隐藏流程和组织冲突，把未知转成跨团队实验与可复用发现机制 |

区分追问：**“哪条新证据会让你改变第一阶段范围？”** 如果只能继续解释原方案，通常还没有显示 4 分所需的组织学习。

## 2. 业务价值、产品判断与采用

| 等级 | 可观察行为 |
| --- | --- |
| 1 | 用 demo、准确率、使用次数代替用户结果；用强制采用掩盖价值问题 |
| 2 | 有业务指标或培训，但没有工作流数据、分群和停止条件 |
| 3 | 连接用户动作、采用、任务结果、系统风险和阶段决策 |
| 4 | 用分群实验重定义低价值方向，并将跨客户机制转成产品或明确不产品化 |

区分追问：**“如果使用次数上升但人工修改和处理时间没有改善，你会怎样决定？”**

## 3. 编码、调试与端到端交付

| 等级 | 可观察行为 |
| --- | --- |
| 1 | 主路径不可运行；随机修改；无视错误、权限或数据损坏 |
| 2 | 在提示下完成 happy path，测试和错误模型不足 |
| 3 | 实现正确可读，覆盖边界与错误；用假设和最小复现调试，并说明生产边界 |
| 4 | 主动加入契约、故障和安全测试，降低后续交付与维护成本 |

区分追问：**“请构造一个会让当前实现产生错误业务结果、但任务仍显示成功的输入。”**

## 4. 数据工程与系统设计

| 等级 | 可观察行为 |
| --- | --- |
| 1 | 罗列组件；假设数据干净；把任务成功当成数据正确 |
| 2 | 有主路径、清洗和重试，但身份、状态、语义与恢复不完整 |
| 3 | 从规模和约束推导数据/控制/证据流，定义身份、版本、幂等、删除、回放和回滚 |
| 4 | 管理语义冲突、消费者迁移、爆炸半径、演进和跨团队 owner |

区分追问：**“同一对象没有内容变化，但权限撤回；你的数据、索引、缓存和引用分别何时收敛？”**

## 5. AI 应用工程

| 等级 | 可观察行为 |
| --- | --- |
| 1 | 默认 RAG/Agent；模型输出直接触发高风险动作；没有终止和恢复 |
| 2 | 知道检索、工具、memory、MCP 等组件，但状态和失效边界依赖理想条件 |
| 3 | 按任务和风险选择规则、检索、生成、工作流或 Agent；控制上下文、状态、预算、工具和人工介入 |
| 4 | 将可控执行、评测、策略和复用接口沉淀为跨场景产品能力，并知道何时退出 Agent |

区分追问：**“工具已经成功但响应丢失，任务恢复依据什么状态继续？”**

## 6. 评测、可靠性、观测与成本

| 等级 | 可观察行为 |
| --- | --- |
| 1 | 只看总准确率；风险发生后仍等待根因；日志无法连接版本和结果 |
| 2 | 有黄金集、trace 和监控概念，但切片、门禁、回放与 owner 不完整 |
| 3 | 固定请求和版本，分层评测，风险门禁，灰度、回退、runbook 与线上反馈完整 |
| 4 | 管理 judge 与数据漂移、隐私/可诊断取舍、事故预算和持续反馈机制 |

区分追问：**“总分恢复了，哪个高风险切片仍能阻止放量，为什么？”**

## 7. 安全、权限与治理

| 等级 | 可观察行为 |
| --- | --- |
| 1 | 用 prompt 代替授权；重复不可逆动作；绕过审计或跨租户边界 |
| 2 | 提 RBAC、人工审核和脱敏，但身份传播、默认拒绝和恢复不清 |
| 3 | 身份与策略贯穿检索、模型、工具、缓存和导出；副作用有幂等、审批、审计和撤销 |
| 4 | 用威胁模型和对抗评测验证控制，管理委托、供应链、break-glass 和跨系统责任 |

区分追问：**“谁有权批准、审批者看到什么、重复请求怎样处理、撤权后缓存何时失效？”**

## 8. 沟通、领导力、交接与产品化

| 等级 | 可观察行为 |
| --- | --- |
| 1 | 全答应或硬拒绝；隐藏风险；把团队成果全部归给自己 |
| 2 | 能解释和升级，但替代路径、owner、期限和证据不足 |
| 3 | 结论、依据、取舍和下一步清楚；能拒绝不安全范围并保持客户进展；交接可运营 |
| 4 | 面向不同角色不失真地调整信息，将重复现场问题变成有 owner、迁移和第二场景证据的杠杆 |

区分追问：**“这次客户例外为什么值得或不值得进入产品？第二个场景怎样验证？”**

## 9. 三条总校准规则

1. **完整的 3 分不是不够 senior。** 它表示能够独立、安全交付。
2. **4 分必须看见杠杆。** 第二场景、组织 owner、迁移、退出或可复用机制不能靠想象补齐。
3. **危险行为不能被平均。** 明确的一票否决必须单列，即使其他维度很强。
