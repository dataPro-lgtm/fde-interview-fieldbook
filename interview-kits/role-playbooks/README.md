# 岗位定向作战包

> 把一条公开 JD 转成自己的证据、训练顺序和面试验证问题，而不是猜题。

## 先选主轴，不要同时扮演三种人

FDE 的共同责任是发现问题、亲手交付、进入生产并沉淀产品能力，但不同岗位考察的工程主轴并不相同。一个数据平台 FDE 候选人如果把主要时间花在背 Agent 框架，一个 AI FDE 候选人如果完全讲不清评测和工具副作用，都会出现“知识不少，证据不对位”的问题。

本目录提供三种训练入口：

| 角色包 | 更看重的工程主轴 | 先证明什么 | 不要误读成什么 |
| --- | --- | --- | --- |
| [AI / Agent FDE](ai-agent-fde.md) | 工作流选择、LLM 系统、评测、工具与上线 | 能把不确定模型放进可负责的生产流程 | 会调用模型或会背 Agent 名词 |
| [数据平台 FDE](data-platform-fde.md) | 数据契约、同步、质量、分布式系统与运营界面 | 能让持续变化的数据可靠进入客户决策 | 只会搭离线管道或只会写 SQL |
| [受监管 AI 部署 FDE](regulated-ai-fde.md) | 权限、证据、审批、审计、变更治理与责任边界 | 能在高风险环境里让系统可用且可追责 | 罗列合规术语或把安全等同于禁止使用 |

这些不是职位名称分类器。一条 JD 可能同时包含两到三条主轴。请选择一个主角色包，再从第二个角色包补一项明显短板。若平均练三套，你往往只会留下三套浅答案。

## 使用顺序

```mermaid
flowchart LR
    A[保存公开 JD 与核验日期] --> B[区分事实、假设与个人证据]
    B --> C[选择一个主角色包]
    C --> D[完成证据矩阵]
    D --> E[做一轮限时模拟]
    E --> F[只修两个高风险缺口]
    F --> G[向招聘方确认流程]
    G --> H[根据新信息更新计划]
```

1. 先读[岗位定向方法](../../docs/zh-CN/14-job-targeting.md)，不要直接跳到技术清单。
2. 使用[岗位定向工作包](../worksheets/job-targeting-pack.md)拆解目标 JD。
3. 选择一个角色包，把每项“我会”换成可展示、可追问的证据。
4. 查看[完整示例](worked-example.md)，理解如何诚实处理相邻经验和真实缺口。
5. 用[角色定向模拟](../mock-loops/role-targeted/README.md)做一次 75 分钟盲练，再与评审独立评分。

## 事实边界

角色包中的“公开信号”来自项目登记的一手岗位页或官方资料，核验日期和来源 ID 记录在 [`data/sources.json`](../../data/sources.json) 与 [`data/role-playbooks.json`](../../data/role-playbooks.json)。它们用于解释能力为何重要，不用于断言某家公司一定采用某套面试流程。

文中的“可能出现的面试面”都是训练假设。真实轮次、编程形式、是否允许工具、客户案例占比和出差要求，应由候选人向招聘方确认。公开 JD 已下线时，只能说明页面状态变化，不能自动推导岗位消失或招聘趋势逆转。

## 什么算完成

完成一个角色包，不是把页面读完，而是留下以下五项产物：

- 一页目标岗位简报，事实和推断分栏；
- 六条以内的证据矩阵，每条都能指出个人决策和可展示材料；
- 两段项目故事，分别能讲 2 分钟和 10 分钟；
- 一次技术场景和一次客户压力场景的录像；
- 一次角色定向盲练和引用原话的独立评分；
- 一份缺口清单，明确哪些只能说“设计练习”，不能包装成生产经历。

如果这些产物不存在，继续读更多岗位资料通常不会提高面试表现。
