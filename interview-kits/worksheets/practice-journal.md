# FDE 刻意训练日志

> 这是一份证据日志，不是学习打卡表。每次训练只处理一个主要风险，留下可以复核的输入、行为、产物和下一次修改。不要记录真实客户名称、保密数据、面试官身份或泄露题目。

## 1. 本轮训练身份

```text
日期：
训练路径：7 天 / 14 天 / 30 天 / 自定义
路径中的 session：
目标角色或角色族：
训练方式：独练 / 同伴主持 / 独立评审
本轮时间盒：
```

## 2. 先写一个要改变的行为

```text
当前风险行为：
它为什么会让面试官或客户担心：
出现这个行为的触发条件：
本轮替代行为：
什么可以证明我真的改了：
```

错误示例：“提升系统设计能力。”这无法观察。

可观察示例：“听到需求后，先复述用户动作、当前基线和最高风险；在这些信息明确前，不画组件架构。”

## 3. 事实与证据边界

用 D/A/E/G 标记本轮要使用的经历。不要因为表达需要而升级证据等级。

```text
主张一：
证据等级：D / A / E / G
可检查产物：
不得越过的边界：

主张二：
证据等级：D / A / E / G
可检查产物：
不得越过的边界：
```

- **D — Direct：** 自己在真实责任范围内做过，并能解释决策和结果；
- **A — Adjacent：** 做过相邻问题，但规模、权限或责任不同；
- **E — Exercise：** 在合成或公开环境完成的设计和实现；
- **G — Gap：** 当前没有足够证据，必须保留为缺口。

## 4. 训练前预测

```text
我最可能在哪一步失去主线：
主持人最可能追问什么：
如果出现新证据，我预计哪项决定会改变：
本轮明确不练什么：
```

## 5. 原始证据记录

训练结束后先记录事实，不急着评价自己。

```text
证据一
时间或位置：
我的原话、白板或代码行为：
当时掌握的证据：
产生的结果：

证据二
时间或位置：
我的原话、白板或代码行为：
当时掌握的证据：
产生的结果：
```

若没有录像，至少保留决策备忘录、代码 diff、测试输出、架构草图或评分人的逐字摘录。只写“整体表现不错”不算证据。

## 6. 评分不是感受

使用对应案例评分表或 [FDE 总评分表](../rubrics/master-scorecard.md)。

```text
评分者：自己 / 同伴 / 独立评审
最低的两个行为锚点：
支持评分的原话或产物：
评分者信心：高 / 中 / 低
如果信心低，缺少什么证据：
是否触发一票否决：
```

自评和独立评分必须分开保存，不能求平均后抹掉分歧。

## 7. TRACE 复盘

```text
Trigger — 什么信息或压力触发了问题：
Response — 我实际做了什么：
Assumption — 哪个未经验证的假设支撑了行为：
Consequence — 对答案、系统或客户产生什么影响：
Experiment — 下一轮怎样用最小实验验证改法：
```

复盘必须定位到首个可替换行为。不要用“准备不足”“紧张”作为最终根因。

## 9. 第二次尝试对比

```text
问题界定：第一次 / 第二次 / 证据变化 / 仍未解决
取舍与边界：第一次 / 第二次 / 证据变化 / 仍未解决
技术正确性：第一次 / 第二次 / 证据变化 / 仍未解决
上线与运营：第一次 / 第二次 / 证据变化 / 仍未解决
客户沟通：第一次 / 第二次 / 证据变化 / 仍未解决
```

如果第二次没有改善，如实记录。训练的目标是暴露风险，不是制造漂亮曲线。

## 10. 周期复盘

完成一条路径后回答：

1. 哪两个行为在不同练习中重复出现；
2. 哪个产物最能证明真实能力，为什么；
3. 哪个模板没有帮助，是否因为说明、时机或前置能力不对；
4. 哪个步骤仍需要作者或主持人额外解释；
5. 哪项证据从 G 变成 E、从 E 变成 A，依据是什么；
6. 下一周期只保留哪三个训练目标。

## 11. 隐私检查

- [ ] 没有真实客户名称、个人身份、内部域名或访问凭证；
- [ ] 没有复制付费材料或泄露面试题；
- [ ] 合成数据和练习经历已经明确标注；
- [ ] 分享前已删除录屏中的通知、浏览器标签和个人信息；
- [ ] 评审反馈引用行为证据，不记录面试官或雇主隐私。
