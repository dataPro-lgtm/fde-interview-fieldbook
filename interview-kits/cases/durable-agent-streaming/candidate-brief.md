# 候选人简报：多 Pod 长任务与断点续传

## 公开背景

一个研究型 Agent 通常运行 3—20 分钟，期间会检索资料、调用内部工具并持续向浏览器输出进度。服务运行在 Kubernetes 多 Pod 环境，前端通过 SSE 接收内容。

目前请求、Agent 内存状态和 SSE 连接都在同一个 Pod。用户关闭页面后重新打开，只有负载均衡再次命中原 Pod 才能继续；Pod 被驱逐时任务和输出一起丢失。团队用 sticky session 缓解了问题，但发布和扩缩容仍经常导致失败。

你需要设计一个不依赖原 Pod 的生产方案，同时保持流式体验，并定义迁移路径。

## 你的任务

1. 明确客户端断开、任务取消、Worker 失败和工具部分成功的不同语义；
2. 设计任务创建、领取、心跳、执行、事件追加、重连、恢复和终止流程；
3. 说明多个 Worker 如何避免同时推进同一个任务；
4. 定义事件顺序、游标、重复投递和历史压缩；
5. 给出从 sticky session 迁移、灰度和回退方案。

## 交付物

- 数据流、控制流与事件流；
- 任务和步骤状态机；
- 重连、租约、幂等、取消和恢复契约；
- SLO、容量和观测指标；
- 分阶段迁移与故障演练计划。
