# 主持人简报：多 Pod 长任务与断点续传

## 运行流程

| 时间 | 环节 | 主持动作 |
| --- | --- | --- |
| 0—5 分钟 | 复述 | 只澄清题意 |
| 5—20 分钟 | 发现 | 释放当前拓扑与流量事实 |
| 20—40 分钟 | 设计 | 追问任务身份、状态、租约和事件游标 |
| 40—55 分钟 | 故障注入 | 释放重连时间线和 Pod 驱逐 |
| 55—65 分钟 | 迁移决策 | 要求明确一致性边界和回退 |
| 65—75 分钟 | 评分 | 记录原话和未覆盖故障 |

## 证据释放

### 第一轮：询问任务时长、工具副作用、状态或流量

释放 `artifacts/round-1-current-topology.md`。

### 第二轮：候选人给出持久化方案或询问实际失败

释放 `artifacts/round-2-event-timeline.csv`。同一任务在租约过期边界被两个 Worker 短暂领取，外部工具已经成功但第一个 Worker 未提交步骤完成。

### 第三轮：40 分钟压力注入

释放 `artifacts/round-3-failure-injection.md`。

应观察候选人是否把“重新订阅输出”和“重新执行任务”分开。SSE 只是消费事件的界面；任务真相、步骤检查点和工具执行结果必须位于可共享持久层。

## 追问

- 用户关闭页面是否应该取消任务？谁有权取消？
- SSE 重连带来的 `Last-Event-ID` 能解决哪些问题，不能解决哪些？
- Worker 在租约过期后又恢复，怎样避免继续写入？
- 工具已成功、步骤 checkpoint 未写入时如何恢复？
- 每个 token 都写数据库是否合理？怎样分层保存？
- 事件至少一次投递时前端和下游怎样去重？
- 发布新 Agent 版本时，运行中的任务使用哪个版本？

## 评分

使用 [`rubric.md`](rubric.md)。高分回答应覆盖任务可寻址性、单写者或 fencing、步骤级幂等、事件重放、取消权限、版本固定和迁移演练。
