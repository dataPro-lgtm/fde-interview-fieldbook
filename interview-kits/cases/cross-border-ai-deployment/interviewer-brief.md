# 主持人简报：跨境企业 AI 部署

## 运行流程

| 时间 | 环节 | 主持动作 |
| --- | --- | --- |
| 0—10 分钟 | 复述与边界 | 观察是否声明需客户法务/安全确认 |
| 10—30 分钟 | 发现 | 释放当前数据流和角色 |
| 30—55 分钟 | 设计 | 追问数据最小化、区域、权限和供应商 |
| 55—70 分钟 | 压力注入 | 释放控制矩阵与集中日志要求 |
| 70—80 分钟 | 阶段决策 | 要求六周计划、停止和退出条件 |
| 80—90 分钟 | 评分 | 记录事实、假设与 owner 分配 |

## 证据释放

### 第一轮：询问数据类别、业务目的、用户、区域或责任人

释放 `artifacts/round-1-data-flow.md`。若候选人直接引用某法规条文作结论，提醒具体适用性未提供，要求转成待确认问题和工程选项。

### 第二轮：提出目标架构或询问控制要求

释放 `artifacts/round-2-control-matrix.csv`。矩阵显示设备手册可共享，但客户升级记录和员工备注限制更多；模型供应商保留策略尚未确认。

### 第三轮：55 分钟压力注入

释放 `artifacts/round-3-pressure-injection.md`。

高分候选人会提出区域内检索和敏感数据处理、最小日志、去标识、统一控制面与区域数据面、供应商契约确认、分阶段 shadow/assist，以及当审批不完整时缩小范围。

## 追问

- “数据不出境”需要落到哪些系统和运维路径？
- 统一模型 API 是否意味着所有输入都可以发送？
- 只删除日志中的姓名，是否已经完成去标识？
- 中央团队怎样排障而不获取完整敏感 prompt？
- 两地共用评测集时，怎样避免复制受限样本？
- 供应商更换或退出时，数据、密钥、缓存和审计如何处理？
- 六周不能完成所有确认时，怎样仍交付可验证价值？

## 评分

使用 [`rubric.md`](rubric.md)。评分看工程责任和边界，不看候选人能背多少法规名称。
