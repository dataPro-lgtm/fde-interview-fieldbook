# 第三轮证据：完整变更记录

主应用确实没有发布，但生产环境存在以下变化。

## Knowledge sync

- `knowledge-sync 2.6.1`更新了第三方内容API客户端；服务仍能完成认证和请求；
- 新客户端默认每页20条，并把下一页字段从 `next_page` 改为 `next_cursor`；现有wrapper只读取第一页；
- 同步任务的成功条件是“所有collection都返回HTTP 200”，没有比较文档数、删除数或上一版本差异；
- 周一08:45，自动发布器把只有3691份文档的新索引设为active；旧完整索引仍然保留，可在两分钟内切回；
- ACL过滤本身正常，尚无跨租户证据。

## Tool gateway and workflow

- 为降低延迟，`credit_tool`回调超时从8秒改为3秒；第三方账务接口p99约为6秒；
- 超时后workflow按“未完成”创建新run，最多重试一次；
- 每次重试使用 `workflow_run_id + tool_call_id` 作为幂等键，因此同一客户case的第二次run拥有新键；
- 第三方接口支持调用方提供幂等键，也支持按业务reference查询结果，但当前集成都没有使用；
- 14个重复案例中，第一次调用均已在账务方成功，只是响应晚于3秒。

## Dashboard

- `workflow_success`在一个月前改为把 `completed` 和 `partial` 都视作成功，目的是区分系统崩溃与可人工接管；
- dashboard没有同时展示证据完整率、工具副作用唯一性或人工接管量；
- 新索引发布门禁只检查构建任务状态、schema和随机十个查询，不检查文档覆盖率与高风险意图回放。
