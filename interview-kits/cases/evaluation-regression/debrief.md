# 参考复盘：AI 评测指标断崖式回归

## 关键判断

准确率下降首先是一个需要验证的观测，但账户安全误路由是已经发生的业务风险。两者不能互相替代：先保护高风险请求，再验证测量链和真实系统行为。

根因定位不是列可能性，而是固定一个请求集合和版本矩阵，寻找数据进入、标签解析、prompt 构造、模型决策、工具执行、输出映射和指标计算中的第一处偏离。

## 参考推演

1. 将账户安全等高风险意图切到人工或旧稳定路径，冻结当前版本和样本；
2. 核对指标分母、标签 schema、样本去重、时间窗口和评测代码；
3. 从发布前保存的请求建立固定回放集，记录数据、标签、prompt、模型解析 ID、工具、策略和代码版本；
4. 先用旧全链重现基线，再一次替换一个变量；
5. 对比路由原始输出和最终工具动作，确定第一偏离层；
6. 修复标签扁平化与评测口径，同时检查 prompt 是否让真实安全意图退化；
7. 按风险切片 shadow、canary、灰度，任何安全切片越界立即回退；
8. 将此次样本进入版本化黄金集，发布清单必须可回放。

## 常见失败

- 看到三个变更就一起回滚，恢复了但无法知道原因；
- 只查模型输出，不查标签和指标代码；
- 评测修复后总分恢复，就忽略线上安全误路由；
- 使用模型别名却不记录解析到的具体版本；
- 回归集只增加一个 happy path；
- 发布门禁只看全局平均值。

## 可以带走的机制

AI 回归的通用排查是：**保护高风险流量、验证测量、固定请求与版本、定位第一偏离层、一次一变量、切片恢复和沉淀回归门禁**。
