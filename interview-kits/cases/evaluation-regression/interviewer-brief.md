# 主持人简报：AI 评测指标断崖式回归

## 运行流程

| 时间 | 环节 | 主持动作 |
| --- | --- | --- |
| 0—5 分钟 | 复述 | 只澄清题意 |
| 5—20 分钟 | 保护与测量 | 释放版本矩阵 |
| 20—40 分钟 | 实验设计 | 追问固定变量和首个偏离层 |
| 40—55 分钟 | 切片注入 | 释放离线切片和标签变化 |
| 55—65 分钟 | 恢复决策 | 要求给出灰度与机制修复 |
| 65—75 分钟 | 评分 | 记录证据和过早结论 |

## 证据释放

### 第一轮：询问指标口径、样本、版本或线上影响

释放 `artifacts/round-1-version-matrix.csv`。如果候选人直接归因 prompt，追问如何排除标签和计算变化。

### 第二轮：提出回放矩阵或要求切片

释放 `artifacts/round-2-sliced-evaluation.csv`。安全意图下降最严重；新同步把多标签样本扁平化，评测脚本仍按旧主标签计算。

### 第三轮：40 分钟压力注入

释放 `artifacts/round-3-pressure-injection.md`。

候选人不必一步猜中最终原因，但必须建立一次只改变一个变量的实验，并区分“指标计算错误”和“真实路由也变差”可以同时存在。

## 追问

- 如果评测标签坏了，是否说明线上没有问题？
- 怎样重放同一请求并固定 prompt、模型、检索和工具？
- 模型别名没有变化记录，怎样缩小不确定性？
- 总准确率恢复后为什么仍不能放量？
- 高风险意图应该使用怎样的门禁和人工保护？
- 哪个字段能证明路由错误来自模型决策，而不是工具返回？
- 修复评测脚本以后，历史趋势怎样重算和标注？

## 评分

使用 [`rubric.md`](rubric.md)。高分回答会先保护账户安全意图，验证测量链，再以固定请求和版本矩阵定位真实回归，并补风险切片门禁。
