# 候选人简报：连接器从定制走向产品能力

## 公开背景

一家 AI 数据平台为五个企业客户开发了文档和工单连接器。每个项目最初都在两到四周内交付，但团队复制旧代码后按客户修改，已经形成五个分支。

最近上游 API 认证升级，五个分支需要分别修复；其中两个客户在回填时出现重复数据，一个客户的删除事件没有进入检索索引。销售同时承诺三周内支持第六个源系统。

你作为 FDE 需要决定哪些能力应该产品化、怎样迁移现有客户，以及第六个连接器还能否按期交付。

## 你的任务

1. 对比五个连接器的共同机制与真实变化维度；
2. 定义连接器契约、适配层、配置边界和运营状态；
3. 设计版本兼容、测试、发布、回填、删除和恢复；
4. 给出现有分支迁移、双跑、回退和退出策略；
5. 判断第六个连接器的承诺、thin slice 和风险沟通。

## 交付物

- 共同核心与变化维度矩阵；
- 连接器生命周期、接口和错误模型；
- 测试、观测与运营控制面；
- 分批迁移和回退计划；
- 对销售和客户的范围、时间与证据说明。
