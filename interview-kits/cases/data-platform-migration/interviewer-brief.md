# 面试官手册：经典数据平台迁移

本文件包含完整事实和释放顺序。不要在开场一次性读完，也不要要求候选人猜中术语。候选人问到相应信息类别时，应提供事实并追问它会改变什么决定。

## 运行流程

| 时间 | 主持动作 | 观察重点 |
| --- | --- | --- |
| 0—5 分钟 | 候选人复述任务 | 是否区分迁移目标、业务连续性和退役压力 |
| 5—20 分钟 | 回答发现问题，释放第一轮事实 | 用户、事实来源、数据语义、范围和风险排序 |
| 20—40 分钟 | 要求画迁移与验证方案 | snapshot/CDC衔接、幂等、删除、对账、恢复 |
| 40—55 分钟 | 提供数据样本和切换压力 | 是否用证据修订方案，而非防守原答案 |
| 55—65 分钟 | 要求明确 go/no-go | 决策、门禁、owner、降级和下一次评审 |
| 65—75 分钟 | 双方独立评分 | 先记原话，再打开复盘 |

候选人如果直接开始画目标架构，先问：“你现在依赖了哪些尚未验证的假设？”不要代替他补发现。

## 证据释放

### 第一轮：发现事实

当候选人询问规模、系统、读写用户、时间或数据所有权时，使用 [`round-1-system-inventory.md`](artifacts/round-1-system-inventory.md)。不要求其逐项问到，但只释放问题覆盖的信息类别。

应主动澄清两点：十周期限是管理目标，不是已经批准的风险豁免；“切换”同时包含报表、客服查询和订单写入，三者不必同一天完成。

### 第二轮：数据证据

候选人提出数据剖析、对账或切换门禁后，提供：

- [`round-2-data-profile.csv`](artifacts/round-2-data-profile.csv)
- [`round-2-reconciliation.csv`](artifacts/round-2-reconciliation.csv)

要求他说明：哪些差异可能是正常业务语义，哪些已经足以阻断切换；下一步要查到记录级、事件级还是指标定义级。

### 第三轮：切换压力

方案初步完成后，完整朗读 [`round-3-cutover-injection.md`](artifacts/round-3-cutover-injection.md)。不要暗示标准答案。候选人可以选择延期全量切换、只切读流量、继续双轨或提出其他方案，但必须说明风险、代价和下次决策证据。

## 追问

根据候选人的薄弱处选择三到四项，不要全部问完：

1. 全量快照进行到一半时源端还在写，如何保证不漏不重？
2. 源端主键在不同地区发生碰撞，你会在什么层修复？
3. 物理删除没有CDC事件，怎样满足隐私删除SLO？
4. 总金额一致能否证明迁移正确？请给一个反例。
5. 业务要求周一切换，但删除和更新仍不完整，你怎样向CIO汇报？
6. 回滚以后，新平台期间产生的新写入如何处理？
7. 哪些能力应该沉淀为平台，哪些是本次客户配置？

如果候选人使用“双写”，继续追问双写失败、顺序不一致和回滚时的权威来源。提到“最终一致”时，追问允许多久、谁承担错误以及如何观测。

## 评分

使用[案例专项评分表](rubric.md)，在阅读[参考复盘](debrief.md)前独立完成。若某项缺少样本，标注“未观察”，不要凭资历想象。

高分不要求选定某个CDC产品。重点观察候选人是否建立以下逻辑链：业务不变量 → 数据语义 → 迁移机制 → 对账证据 → 分阶段切换 → 可恢复决策。
